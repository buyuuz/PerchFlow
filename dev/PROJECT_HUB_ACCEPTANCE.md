# PerchFlow Project Hub V1–V5：隔离环境综合验收报告

## 范围与原则
- 验收基线：`feature/project-hub-v5`（24722e3），整改/专项测试分支：`feature/project-hub-acceptance`。
- 使用 GitHub-hosted Windows Runner 与本地假 API、模拟 cmd/Python 文件；不连接用户电脑、不开真实业务登录、不发布任何商品、不迁移 Windows 计划任务。
- 本次验收**不等于生产环境部署测试**，也不包含真实 Windows 10 IoT LTSC 的桌面自动化兼容性结论。
- `main`、V4、V5 既有分支保持不动；整改仅提交到隔离验收分支。

## 实际发现与整改
1. **P1 — 中英文混排**：默认英文界面仍出现大量固定中文标签。整改：Project Hub 页面增加语言切换，静态和动态内容统一遵循全局 `perch-lang`，支持 zh/en。
2. **P1 — 手机端大量无效留白**：一个项目时仍强制给项目列表 360px 高度。整改：去除强制最小高度，让项目列表自适应，长列表在面板内滚动。
3. **P1 — 异步运行记录串页风险**：用户从 A 项目快速切换到 B，A 的慢响应可能覆盖 B 的执行详情。整改：引入项目与 run_id 请求身份校验，延迟返回的旧日志/历史/文件元数据响应不再污染新选中项目。
4. **P1 — 任务配置写盘失败时内存与磁盘不一致**：旧任务 CRUD 先改内存再保存 TOML，存储异常时可能留下未持久化的运行状态。整改：先将下一版配置通过原子文件保存接口持久化成功，再交换内存配置、更新运行时任务映射并 reload Scheduler；失败不提交。
5. **P3 — 英文计数字面表达**：例如 `checked 1 items` 目前可理解，但语法可进一步润色；不影响执行正确性。

## 自动化功能验收
- Project Hub 现有 V1–V5 任务/文件相关 API、输入预检、文件自动发现、单次历史、运行/停止与 Cron 调度：继续依赖完整 Rust + EXE 模拟回归。
- Edge 专项 UI：桌面中文、英文切换、取消确认不请求后台、按需日志、360/390/768px 不横向溢出、41 项目列表、空状态、API 503、快速切换项目防串页，共 9 个场景，**PASS**。
- 验收截图与 JSON 证据：[GitHub Actions 39526674684](https://github.com/buyuuz/PerchFlow/actions/runs/39526674684)；测试结果制品为 `perchflow-v1-v5-acceptance`。
- 后端写盘失败回滚场景：通过将 CI 临时目录中的 TOML 保存目标替换成目录来稳定制造写盘失败，不修改系统 ACL 或真实文件；确认失败时新建不出现、编辑内容不变、删除不生效。

## 验收仍有的边界
- 本次全部业务操作都使用 MOCK 数据；生产现场部署、开机自启实机、多账户 Windows 桌面/浏览器、系统锁屏及实际账号登录未验证。
- 项目文件仅存储元数据。文件名/路径和脚本原生 stdout/stderr 仍可能包含敏感信息；日志仍需明确点击才能查看，并不代表后台已经脱敏或加密。
- 自动发现受限于用户登记的目录、深度、数量；异常磁盘/并发改动可能产生不完整扫描，必须依赖 `incomplete_scan` 提示。
- 尚不支持单任务独立依赖配置、跨项目 DAG、无上限目录扫描或迁移真实 Windows Task Scheduler。

## 验收结论和放行标准
- 视觉与模拟交互验收：**已通过**（9/9）。
- V1–V5 原有自动化回归：需以验收分支最新提交的 GitHub Windows CI 为准。
- 写盘失败回滚验收：需以最新提交的 Cargo/API 结果为准。
- **在完整 CI 完成前不得合并 main**。即使全部通过，也建议下一步先在隔离的 Windows 测试机上做灰度真实脚本兼容验收，再由用户决定是否合并与部署。

本报告记录代码验收，不声明对用户正在使用电脑进行了实际操作。
