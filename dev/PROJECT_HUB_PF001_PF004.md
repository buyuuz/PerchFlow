# PerchFlow Project Hub — PF-001 至 PF-004 实施与验收

> 开发分支：feature/project-hub-pf001-pf004。独立候选版，不合并 main，不部署到 C2，不执行任何真实发布脚本。

## PF-001：状态与停止竞态
项目页可见时每 2.5 秒更新任务状态，超过 90 秒也继续刷新；运行结束后按同一 run_id 原子更新任务状态、PID 和活动任务映射。停止一个刚完成的任务返回 already_finished 及最终状态，而不是误报「任务不在运行中」。保留手动运行与 Cron 的独立控制。

## PF-002：统一 UI
项目管理复用进程/定时任务的青色主题、顶部导航、语言选择、页面宽度、字号和移动端底部导航。项目选择变为横向滚动入口，每个已登记的 Python 任务占整行。

## PF-003：脚本详情和外部关联文件
一个项目仍能关联多个独立的 Python TaskDef，彼此运行参数、PID、状态、Cron 和日志均独立。点击脚本行或「详情 ↗」进入独立脚本详情页，查看 PID、CPU、内存、运行时长、参数、退出码和运行历史。

仅在用户打开详情时，服务器读取登记的 Python 源码最多 128 KiB，从字符串中推断可能关联的 Excel/TXT/CSV/JSON 等文件路径。显示来源、是否存在、大小、修改时间。不能保证识别动态拼接路径；不运行 Python，不读取 Excel/TXT 正文。

「打开文件」须用户明确点击并确认；服务器重新校验路径归属/扩展名/元数据且必须在 loopback 本地服务下运行，禁止 UNC 网络路径、遍历或可执行文件。Windows 后台 Session 0 不能保证 GUI 能弹出；推荐登录的可交互桌面。

当前版本不会自动把任意项目目录中所有 .py 当成可以执行的脚本。用户可通过「+ Python 任务」分别确认并登记 Photo_AutoPublisher.py 与 sync_photos_to_excel.py；新任务始终默认禁用。

## PF-004：每个脚本最近三次日志
每个 run_id 独立创建一个从 0 字节开始的日志文件，日志显示从 0 行重新计数。当同一个任务的第 4 次真实执行启动后，清理属于它的最旧一份日志，仅保留最近 3 份；另一个任务的日志不会被删除。如任务安全化后的文件名前缀冲突，宁可跳过清理也不误删。

历史执行摘要 history.jsonl 和文件变化元数据独立保留，不随着三次日志正文配额删除。缺失或已清理的历史日志会提示已过期。现有历史日志在首次重新执行该脚本之前不会主动清理；脚本自己产生的 Excel、CSV、TXT 和其他项目日志不会被删除。

## 验证计划
- Windows Cargo 单元/API 测试、Release 编译、原 Cron/取消/超时集成回归。
- Edge 模拟浏览器：旧版 V1–V5 交互、41 项目、语言切换，以及新增实时任务卡、单脚本独立详情、日志需主动查看、文件打开须确认。
- Windows GitHub 临时 runner：真正编译的 PerchFlow EXE 调用两个仅标准库的虚构 Python 脚本，验证每个脚本 PID 与日志独立、A 连续执行四次只保留后三份，B 的日志不受影响。
- 临时目录测试包 Startup/Stop/模拟文件产出，无生产数据或外部账号。
- 只有全部相应 CI 验证通过，才能标注「隔离环境验收通过」。不代表 C2 真实脚本或交互浏览器已验证。

## C2 安全更新（仅在验收通过后）
1. 先确认运行中的真实业务脚本已结束。
2. 双击独立测试版 Stop-Test.cmd。
3. 备份整个现有测试目录，尤其 perch.toml 和 task-logs。
4. 仅从新的 ZIP 中提取 perch.exe，替换现有**测试版目录**的 perch.exe，不覆盖配置。
5. 用原 Start-Test.cmd 启动，先用 Fake/Demo Python 模拟任务验证 UI 与三次日志规则。
6. 禁止为验证刷新而重复执行已提交 TikTok 排期的真实 Photo_AutoPublisher.py。

**本次改动都仅位于 feature 分支，尚未触碰正式 main、C1 或 C2。**
